# Adaptive Agent Orchestrator v0.7.9

[简体中文](#简体中文) · [English](#english)

Release date: 2026-07-30

## 简体中文

### 解决的问题

同一个长期只读审核 source 会跨多个 checkpoint 持续复审。此前 original
source 的恢复收据只按 `source + attempt` 命名并串链：checkpoint07 已用过
attempt 1 后，checkpoint08 再次出现 completed 但缺 final，脚本会错误地把
新恢复接到旧 checkpoint 链上并安全拒绝。系统没有误放行，但合法复审被永久
阻断。

### 本版收益

- 每个 original durable source 的新 checkpoint/input 建立独立 recovery
  cycle。
- cycle 哈希绑定 run、source、role、thread、active milestone/activation、
  checkpoint 与 input manifest。
- 每个 cycle 从 attempt 1 开始，最多三次同 thread、同 role 回收；旧 cycle
  不能延长、重置或授权新 cycle。
- 拒绝跨 checkpoint/input/milestone 串链、旧 receipt 重放、attempt 重置
  旁路，以及跨 source/thread 复用。
- 新 original-source 收据使用 schema 1.2 和带完整 cycle ID 的 canonical
  文件名；历史 schema 1.0 original 与 schema 1.1 replacement 仍可读取。
- `result_pending` 与 completion 继续 fail closed；commentary 和 tool
  progress 仍然只是证据，不是 final。

### 真实采用验证

multi-divination 的长期反方 source 在 checkpoint07 成功恢复过一次后，
checkpoint08 再次丢失 final：

- 正式创建独立 cycle `7705aa4b…` attempt 1，没有覆盖 checkpoint07 历史；
- 同一 source/thread 的最小回收返回正式 final；
- 生成合法 schema 1.3 result receipt 与 source-specific disposition；
- journal 追加 `result_pending → running → completed → validated → adopted`，
  最终 19 条事件，head `22401c24…`；
- completion 仍因开放的业务 P1、traditional/main 未完成和 main evidence
  缺失保持 `BLOCKED`。

该业务 P1 是 multi-divination 的 int/string key `input_hash` 碰撞，不是
Orchestrator 缺陷。Orchestrator 的恢复和完成门按预期工作。

### 验证

- 45 个 PowerShell 脚本解析；
- 56 项恢复协议专项断言；
- 750 项完整自测，59 个非法案例正确拒绝；
- 8 个 reference JSON 文件严格解析；
- Skill Creator 校验；
- 同一独立 Noether 角色动态复攻，P0/P1/P2 均为 0；
- 源码与安装副本 64/64 文件 SHA-256 一致；
- 真实控制面采用 PASS。

### 边界

- 本版不修复平台 `systemError` 或 final 丢失本身。
- 本版不声明生产环境 Token 节省或业务准确率。
- 本版不修改 multi-divination 产品文件，也不把其业务 P1 归因给
  Orchestrator。
- 恢复 cycle 只允许同一 source/role/thread 在绑定的 checkpoint/input 下
  回收 final；它不允许 replacement-of-replacement，也不放宽 P0/P1 门。
- Windows 符号链接夹具因权限限制跳过；Linux/macOS 未动态验证。

编排 policy 仍为 `0.7.6`。v0.7.9 是该 policy 下的恢复收据兼容补丁，不要求
改写一致的现有 run。

## English

### The problem

A long-lived read-only review source can re-review multiple checkpoints. The
previous original-source recovery namespace used only `source + attempt`.
After checkpoint07 had consumed attempt 1, another missing final at checkpoint08
was incorrectly chained to the old checkpoint and safely rejected. Nothing was
accepted incorrectly, but the legitimate review could not continue.

### Benefits

- Every new checkpoint/input for an original durable source opens a separate
  recovery cycle.
- The cycle hash binds the run, source, role, thread, active
  milestone/activation, checkpoint, and input manifest.
- Each cycle starts at attempt 1 and permits at most three same-thread,
  same-role recoveries. An old cycle cannot extend, reset, or authorize a new
  one.
- Cross-checkpoint/input/milestone chaining, old-receipt replay, attempt-reset
  bypasses, and cross-source/thread reuse fail closed.
- New original-source receipts use schema 1.2 and a canonical filename carrying
  the complete cycle ID. Historical schema 1.0 original and schema 1.1
  replacement receipts remain readable.
- `result_pending` and completion remain fail closed. Commentary and tool
  progress remain evidence, never a final result.

### Real adoption

The long-lived adversarial source in multi-divination had already recovered at
checkpoint07, then lost its final again at checkpoint08:

- a separate cycle `7705aa4b…` attempt 1 was created without overwriting the
  checkpoint07 history;
- minimal recovery on the same source/thread returned a formal final;
- valid schema 1.3 result and source-specific disposition receipts were
  generated;
- the journal appended `result_pending → running → completed → validated →
  adopted`, ending with 19 events and head `22401c24…`;
- completion stayed `BLOCKED` because a business P1 remained open,
  traditional/main were unfinished, and main evidence was absent.

That business P1 is an int/string-key `input_hash` collision in
multi-divination, not an Orchestrator defect. Recovery and completion behaved
as designed.

### Validation

- 45 PowerShell scripts parsed;
- 56 focused recovery-protocol assertions;
- 750 full self-test assertions and 59 rejected invalid cases;
- 8 strict reference JSON parses;
- Skill Creator validation;
- dynamic re-attack by the same independent Noether role, with P0/P1/P2 all
  zero;
- 64/64 source and installed Skill files matched by SHA-256;
- the real control-plane adoption passed.

### Boundaries

- This release does not repair platform `systemError` or missing-final
  behavior.
- It does not claim measured production Token savings or business accuracy.
- It does not modify multi-divination product files or classify its business P1
  as an Orchestrator defect.
- A recovery cycle only recovers the same source/role/thread under its bound
  checkpoint/input. It does not permit replacement-of-replacement or relax
  P0/P1 gates.
- The Windows symbolic-link fixture was skipped; Linux/macOS were not
  dynamically validated.

The orchestration policy remains `0.7.6`. v0.7.9 is a recovery-receipt
compatibility patch under that policy and does not require rewriting a
consistent existing run.
