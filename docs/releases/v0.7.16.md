# Adaptive Agent Orchestrator v0.7.16

[简体中文](#简体中文) · [English](#english)

Release date: 2026-07-31

## 简体中文

### 解决的问题

真实长期审核出现了一个跨连续修订的死锁：

- 第一轮同里程碑复审已经完整完成并唯一选定；
- 它仍保留开放 P0/P1，因此依法不能生成主任务最终验收；
- 但旧授权器又要求先有该最终验收，才允许同一里程碑进入下一 checkpoint。

这意味着用户既不能假装问题已经解决，也不能开始下一轮修复后的正式复审。
控制门安全地保持关闭，却没有合法的继续路径。

### 本版修复

- 只在当前 active milestone 是 plan index 0、上一 revision 已完整选定、尚未
  激活 later milestone、没有 pending/partial revision、也没有最终主验收时，
  允许授权同一里程碑的下一次 revision。
- 新 revision 必须使用不同的 checkpoint 和 input，并保持同一 run、source、
  role 与长期审核任务身份。
- schema 1.1 authorization 绑定上一份 selection receipt、精确 selection
  event、写入前 journal head/count，以及上一轮仍开放的每一条 P0/P1 来源
  occurrence：source ID、canonical ID、severity、原文与哈希、状态都必须
  逐项一致。
- 遗漏、降级、改文、跨来源搬运、只保留 canonical 汇总、复用旧 checkpoint、
  stale journal、重复或分叉 revision、pending/later/final-accepted 状态以及
  授权后材料漂移都会在写 journal 前拒绝。
- 首次 revision 的 schema 1.0 兼容路径保持不变；普通 `adopted` 仍是终态，
  不能绕过 revision authorization 重新启动。

### 实际收益

上一轮复审仍有未解决问题时，可以在不修改历史、不伪造“已经验收”、不更换
审核来源的前提下，继续同一阶段的下一轮正式复审。所有旧开放问题必须原样带入，
只有同来源的新 disposition 才能明确解决它们。

真实 checkpoint16 run 中：

- revision index 2 authorization 与两个来源的 fresh re-arm 均成功；
- 两个长期审核来源都返回正式 final，并生成 schema 1.3 result 与各自的
  disposition；
- completed → validated → adopted 生命周期均直接绑定正确证据，无需纠正；
- 唯一 schema 1.1 selection 被追加；
- 原 37 条事件前缀逐字节不变；
- completion 继续因 1 个开放 P0、5 条开放 P1 来源记录和缺少主任务最终验收
  保持 `BLOCKED`；
- 本轮同来源解决的 P1-08 与 A5 没有回流；
- multi-divination 的 90 个产品文件全部保持稳定。

### 验证

- 54 个 PowerShell 脚本解析；
- 149 项 durable milestone/revision 专项断言；
- 91 项恢复协议、45 项物化连续性与 15 项 policy activation 断言；
- 883 项完整自测，59 个非法案例正确拒绝；
- 8 个 reference JSON 文件严格解析；
- Skill Creator 校验；
- 固定 ZIP、功能提交和安装副本 73/73 文件一致；
- 同一独立 Noether 验收角色完成 50/50 动态案例与 9/9 真实形态检查，
  P0/P1/P2 均为 0；
- 真实 authorization → fresh 双审 → result/disposition → selection →
  completion 采用链通过，并保持预期阻断。

### 边界

- 本版不修复平台 `systemError` 或 final 丢失。
- 本版不判断或修复 multi-divination 的业务问题，也没有修改其产品文件。
- 本版不声明生产环境 Token 节省或业务准确率。
- 连续 revision 路径只适用于 plan index 0 的同一 active milestone，不是任意
  历史或里程碑重启机制。
- 本地追加式哈希链不能抵抗攻击者一致重写早期授权和全部后续历史；该威胁仍
  需要外部不可变锚点。
- Windows 符号链接夹具因权限限制跳过；Linux/macOS 未动态验证。

编排 policy 仍为 `0.7.6`。v0.7.16 是该 policy 下的控制补丁，不要求改写
内部一致的现有 plan、run 或 journal。

## English

### The problem

A real long-lived review reached a consecutive-revision deadlock:

- the preceding revision of the active milestone was complete and uniquely
  selected;
- open P0/P1 findings correctly prevented final main-owner acceptance; and
- the old authorizer also required that final acceptance before another
  checkpoint revision of the same milestone could begin.

The gate failed closed, but there was no honest way to continue review without
pretending the open findings were accepted.

### Fix

- Authorize another revision only when the active milestone is plan index 0,
  the preceding revision is complete and selected, no later milestone,
  pending/partial revision, or final acceptance exists, and the new checkpoint
  and input differ.
- Preserve the same run, source, role, and durable reviewer-task identities.
- Bind schema 1.1 authorization to the preceding selection receipt and exact
  selection event, pre-write journal head/count, and every still-open P0/P1
  source occurrence with its source ID, canonical ID, severity, exact
  text/hash, and status.
- Reject omission, downgrade, text drift, cross-source movement,
  canonical-only collapse, checkpoint reuse, stale journal state, duplicate or
  forked revision, pending/later/final-accepted state, and post-authorization
  material drift before journal write.
- Preserve schema 1.0 compatibility for the first revision. Ordinary
  `adopted` remains terminal unless the strict revision authorization applies.

### Benefit

Teams can perform another formal review of the same stage after a repair
without rewriting history, inventing final acceptance, or dropping unresolved
findings. Only a new same-source disposition may resolve an inherited
occurrence.

In the real checkpoint16 run:

- revision-index-2 authorization and fresh re-arm succeeded for both sources;
- both durable reviewers returned formal finals and produced schema 1.3
  results plus source-specific dispositions;
- completed → validated → adopted bound the correct evidence directly;
- one unique schema 1.1 selection was appended;
- the original 37-event prefix remained byte-identical;
- completion stayed `BLOCKED` by one open P0, five open P1 source occurrences,
  and missing final main acceptance;
- same-source resolutions for P1-08 and A5 did not reappear; and
- all 90 multi-divination product-file hashes remained stable.

### Validation

- 54 PowerShell scripts parsed;
- 149 durable milestone/revision focused assertions;
- 91 recovery, 45 materialization-continuity, and 15 policy-activation
  assertions;
- 883 full self-test assertions and 59 rejected invalid cases;
- 8 strict reference JSON parses;
- Skill Creator validation;
- fixed ZIP, functional commit, and installed Skill matched across 73/73 files;
- the same independent Noether role passed 50/50 dynamic cases and 9/9
  real-run-shape checks with P0=0/P1=0/P2=0; and
- the real authorization → fresh dual review → result/disposition → selection
  → completion adoption chain passed while preserving the expected block.

### Boundaries

- This release does not repair platform `systemError` or missing-final behavior.
- It does not judge or repair multi-divination product findings and did not
  modify multi-divination product files.
- It does not claim measured production Token savings or business accuracy.
- Consecutive revision authorization is limited to plan index 0 of the same
  active milestone; it is not a general historical or milestone restart.
- The local append-only hash chain does not resist coherent rewriting of early
  authorization and all later history; that threat still requires an external
  immutable anchor.
- The Windows symbolic-link fixture was skipped; Linux/macOS were not
  dynamically validated.

The orchestration policy remains `0.7.6`. v0.7.16 is a control patch under that
policy and does not require rewriting a consistent existing plan, run, or
journal.
