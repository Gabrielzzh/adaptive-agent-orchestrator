# v0.7.18 — Durable-review recovery and exact correction identity

This release closes fail-closed recovery gaps discovered in append-only durable
review runs. It does not rewrite old journals, change findings, or weaken final
main-owner acceptance.

## What changed

- A pending same-milestone revision with invalid bound control material can be
  abandoned exactly once before any adoptable result lifecycle exists.
- Revision ordinals follow canonical authorization history, so an abandoned
  revision consumes its ordinal without making the next revision incomplete.
- Replacement sources can use current consecutive-revision authority for
  bounded recovery, result generation, and exact selection.
- Documented lifecycle evidence-pointer omissions can be repaired by one
  append-only correction that preserves state and every bound artifact.
- `correction_mode` and `omission_source_node_id` are exact ordinal identities.
  Case changes, surrounding whitespace, and Unicode lookalikes fail before write.

## General orchestration model

The Skill creates an organization shaped by the current task, not a fixed
project template. The invoking Agent is the task lead and chooses the minimum
useful workstreams and hierarchy. Simple work remains one layer. Complex or
multi-project work may add project leads and isolated executors. Executors ask
upward for staffing and never grow an unbounded task tree. Luna High/Max is the
ordinary execution tier; Sol High/Max handles complex leadership, architecture,
ambiguous debugging, and formal review. Terra is non-default; Ultra requires
explicit per-node approval. Writers use isolated worktrees that the lead retires
after safe integration.

## Boundaries

- Only public Codex GPT routes are documented.
- Open P0/P1 findings and missing main-owner acceptance still block completion.
- No product-specific workflow or fixed two-project hierarchy is embedded.
