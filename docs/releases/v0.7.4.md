# Adaptive Agent Orchestrator v0.7.4

Date: 2026-07-30
Channel: Stable

v0.7.4 fixes a field-discovered compatibility gap: an immutable run created
under an older policy could be internally valid yet impossible to resume after
upgrading the Skill.

## The pain this release addresses

A real `0.7.2` durable-review run already contained valid legacy adoption,
recovery, replacement continuity, frozen checkpoint, and thread-read evidence.
The newer validator correctly required the current policy for new plans, but
also rejected the old run. Editing its plan, run metadata, genesis event, or
journal would destroy the identity that the evidence was meant to protect.

The same run already had replacement Workers. Codex returned their task
identities but not their actual runtime models. A safe continuation therefore
had to preserve both facts: the older run must stay byte-identified, and a
requested model must never be presented as an observed model.

## What changed

- A consistent `0.7.2` or `0.7.3` run can activate the `0.7.4` runtime policy
  through an append-only `run-policy-activation.0.7.4.json` receipt.
- The receipt binds the predecessor plan/run/genesis and journal head, exact
  run artifacts, derived source obligations, authorization material, and target
  policy. The old plan, run metadata, genesis, and journal are not rewritten.
- Every later event retains the source `policy_version` and hash-binds the
  effective `runtime_policy_version` plus the exact activation receipt.
- An existing replacement Worker can enter the lifecycle only through an
  explicit adoption action and its exact continuity receipt. Role, source,
  thread, checkpoint, and input must match.
- When Codex does not expose the runtime model, adoption records
  `actual_model=null`, `unverified`, and evidence. It never copies the requested
  route into the actual-model field.
- Adopted replacements consume Worker capacity. Their result receipts still
  remain source-specific, and disposition, re-review, and P0/P1 completion
  gates remain in force.
- Missing or changed predecessor material, repeated or concurrent activation,
  downgrade or skipped target policy, and receipt replay fail closed.

## Validation

- 35/35 PowerShell 7 scripts parse;
- 15/15 run-policy activation assertions pass;
- 45/45 recovery-protocol assertions pass;
- 637/637 full self-test assertions pass;
- 57/57 intentional invalid cases are rejected;
- all 8 bundled reference JSON files parse strictly;
- Skill Creator reports `Skill is valid!`;
- the original independent Reviewer expanded the dynamic attack set to 27
  activation and 55 recovery/adoption assertions, including 12 synchronized
  concurrent-activation rounds;
- final independent verdict: GREEN, P0=0, P1=0, P2=0.

## Limits

- The Skill does not repair platform `systemError` or missing-final behavior.
  It keeps those states blocked and protects their evidence.
- Policy activation does not migrate or edit business artifacts.
- This release does not claim measured production Token savings.
- The Windows symbolic-link fixture was skipped because this environment did
  not permit link creation. Linux and macOS were not dynamically validated.

## 中文说明

v0.7.4 修复一个真实使用中发现的兼容性缺口：旧策略创建的不可变 run 内部
完全一致，却会在升级 Skill 后因 policy 版本不同而无法继续。

### 解决的痛点

真实的 `0.7.2` 长期审核 run 已经包含合法的旧任务接入、三次恢复、
replacement continuity、冻结 checkpoint 和 thread-read 证据。若直接修改
plan、run metadata、genesis 或 journal 来迎合新版本，就会破坏这些证据
保护的身份。

同一 run 的 replacement Worker 已经真实存在，但 Codex 没有公开实际运行
模型。因此继续流程时既不能改写旧链，也不能把请求的模型冒充实际模型。

### 本版更新

- 内部一致的 `0.7.2` 或 `0.7.3` run 可通过追加式
  `run-policy-activation.0.7.4.json` 收据采用 `0.7.4` 运行策略。
- 收据绑定旧 plan/run/genesis、journal head、全部现存产物、推导出的来源
  obligation、授权材料和目标策略；旧文件不改写。
- 激活后的事件继续保留源 `policy_version`，同时绑定
  `runtime_policy_version` 和准确的激活收据。
- 已存在的 replacement Worker 只有凭显式 adoption 操作和准确 continuity
  receipt 才能进入生命周期；角色、来源、thread、checkpoint 和 input 必须
  完全一致。
- 平台不公开实际模型时，只能记录 `actual_model=null / unverified / 证据`，
  不能把请求路由写成实际模型。
- adopted replacement 占用 Worker 容量；结果回执仍按来源隔离，原有
  disposition、复审和 P0/P1 完成门保持不变。
- 缺失或修改旧材料、重复或并行激活、降级或跳版本、跨范围重放都会
  fail closed。

### 验证与边界

本版通过 35/35 PowerShell 解析、15/15 策略激活专项、45/45 恢复协议专项、
637/637 完整自测、57/57 非法案例拒绝、8/8 JSON 和 Skill Creator 校验。
原独立 Reviewer 将动态攻击扩展到 27 项 activation、55 项
recovery/adoption，并执行 12 轮同步并行激活，最终 GREEN，P0/P1/P2 均为 0。

Skill 不修复平台 `systemError` 或 final 丢失，不迁移或修改业务产物，也不
宣称已证明生产环境 Token 节省。Windows 符号链接夹具因权限跳过；
Linux/macOS 尚未动态验证。
