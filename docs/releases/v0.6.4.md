# v0.6.4 candidate / 候选版

Date / 日期: 2026-07-26

## 中文

v0.6.4 增加两个确定性工具，但不增加新的 Agent、Router 或用户预算配置。

### 校准账本

`Manage-CalibrationLedger.ps1` 把通过哈希校验的 reconciliation 收据追加到
项目内 `.orchestrator/calibration.jsonl`。记录不包含任务文本、摘要或 Thread
ID，并按 Codex App 版本、host、执行模式和策略版本分组。

```powershell
pwsh -File scripts/Manage-CalibrationLedger.ps1 `
  -Action Add -ProjectRoot <project-root> -RunDirectory <run> `
  -MinWindowUsed 20 -AppVersion <version> -HostKind <kind> `
  -ExecutionMode local -PolicyVersion 0.6.4

pwsh -File scripts/Manage-CalibrationLedger.ps1 `
  -Action Summary -ProjectRoot <project-root>
```

账本记录的是“最后未发现与首次发现之间的观测区间”和完整快照跨度，不是
精确平台延迟。P90 使用 nearest-rank 算法；坏行会把完整性标为 degraded。
由于现有 span 不能证明创建到可见的延迟，本版固定返回
`insufficient-visibility-evidence`，不会据此建议或自动修改等待窗口。

### 非物化派遣预览

`Preview-OrchestrationDispatch.ps1` 在创建持久 Worker 前展示当前 wave 的
角色、拓扑、模型、effort、输入引用、写入范围和初始任务包字符数。

```powershell
pwsh -File scripts/Preview-OrchestrationDispatch.ps1 `
  -PlanPath <plan.json> -WorkspaceRoot <project-root> -Wave 1
```

它不创建 run、reservation、Thread 或 subagent，也不在项目中写预览文件。
`initial_packet_chars` 只表示初始任务包长度，不是总 Token 或金额。
早期 wave 的依赖只会使节点 `plan_eligible`，不会被错误称为
`runtime_ready`；reuse 校验在 handoff 实际存在前保持 deferred。

### 额外修复

单快照 reconciliation 收据现在稳定写入浮点零值，避免生成后因 `0` 与
`0.0` 的序列化差异无法通过自己的哈希校验。

### 验证

- 24 个 PowerShell 脚本通过语法解析；
- 503 项自测断言通过；
- 50 份故意构造的非法计划均被正确拒绝；
- Skill Creator 结构校验待最终交接冻结包执行；
- Windows 符号链接测试因当前权限不足而跳过。

本候选版尚未发布 GitHub，也没有把 fixture 测试描述成真实平台延迟证明。

## English

v0.6.4 adds two deterministic tools without adding a Router Agent, a new
worker tier, or a user-configured budget.

### Calibration ledger

`Manage-CalibrationLedger.ps1` appends hash-verified reconciliation
observations to `.orchestrator/calibration.jsonl`. Records exclude task text,
summaries, and thread IDs and are grouped by app version, host, execution mode,
and policy version.

The ledger stores observation intervals and snapshot spans, not exact platform
visibility latency. It uses nearest-rank percentiles and returns
`insufficient-visibility-evidence` instead of deriving a window change from
snapshot spans.

### Non-materializing dispatch preview

`Preview-OrchestrationDispatch.ps1` reports the planned wave's role, topology,
model, effort, references, write scope, and initial packet characters without
creating a run, reservation, thread, or subagent.

`initial_packet_chars` is an initial-context proxy only. Structural
`plan_eligible` status is distinct from runtime readiness, and reuse
verification remains deferred until the handoff exists.

### Additional fix and validation

Single-snapshot reconciliation receipts now preserve a stable floating-point
zero under hash verification.

- 24 PowerShell scripts parse successfully;
- 503 self-test assertions pass;
- 50 intentionally invalid plans are rejected;
- final frozen-package Skill Creator validation remains part of handoff
  preparation;
- the Windows symbolic-link fixture was skipped because this session lacks link
  creation permission.

This candidate is not yet published to GitHub and does not present fixture
observations as production latency evidence.
