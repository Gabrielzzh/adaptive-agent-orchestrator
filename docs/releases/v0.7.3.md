# Adaptive Agent Orchestrator v0.7.3

Date: 2026-07-30  
Channel: Stable

v0.7.3 is a field-driven patch for two gaps found while v0.7.2 coordinated
real durable reviewers. It records model identity honestly when Codex does not
expose the runtime model, and it gives a replacement task one bounded recovery
epoch without permitting an endless replacement chain.

## The pain this release addresses

Codex may create a durable task without returning its actual runtime model.
The old event contract required a concrete model anyway. Recording the
requested Sol route as actual would fabricate evidence; leaving the field empty
blocked the lifecycle and prevented a legitimate replacement result receipt.

A second failure appeared when an authorized replacement itself completed
without a final answer. Original recovery receipts had already consumed
attempts 1–3, but the protocol had no separate namespace for the replacement.
A naive extension could also reset attempts through another directory or label
the replacement as an original source to create a replacement-of-replacement.

## What changed

- A materialized Worker may record `model_id=null`,
  `model_verification_state=unverified`, and bound source or observation
  evidence when the platform omits the actual model.
- The requested route stays in the immutable plan. It is never relabeled as the
  observed model.
- Journal hashing protects model verification state and evidence. Reduced
  state, completion output, and schema 1.1 task receipts preserve whether every
  actual model was verified.
- An authorized replacement that loses its final gets a distinct
  `replacement` recovery stage with its own canonical attempt filenames.
- Replacement recovery binds the existing replacement-continuity receipt,
  replacement thread, logical source, role, checkpoint, and input.
- Recovery stage is derived from materialization and `replacement_pending`
  journal events rather than trusted caller input.
- Attempts are single-use, sequential, canonical to the run receipts
  directory, and capped at three. Exhaustion cannot transition back to
  `running`.
- Replacement recovery can recover the same replacement result, but it cannot
  authorize another replacement.

## Validation

- 33/33 PowerShell 7 scripts parse;
- 41/41 recovery-protocol assertions pass;
- 617/617 full self-test assertions pass;
- 57/57 intentional invalid cases are rejected;
- all 8 bundled reference JSON files parse strictly;
- Skill Creator reports `Skill is valid!`;
- the independent Reviewer dynamically re-attacked requested-as-actual,
  missing evidence, journal tampering, alternate-directory attempt reset,
  fourth recovery, stage relabeling, and replacement-of-replacement;
- final independent verdict: GREEN, P0=0, P1=0, P2=0.

## Limits

- The Skill does not make Codex expose an actual model that the platform omits.
  It records that fact as unverified.
- The Skill does not fix platform `systemError` or missing-final behavior. It
  keeps those states blocked and constrains recovery evidence.
- This release does not claim measured production Token savings.
- The Windows symbolic-link fixture was skipped because this environment did
  not permit link creation. Linux and macOS were not dynamically validated.

## 中文说明

v0.7.3 来自 v0.7.2 的真实长期任务采用反馈，修复两个会阻断审核闭环的问题：
平台创建任务后不返回实际模型；以及 replacement 自身显示完成却没有 final。

### 解决的痛点

平台不公开实际模型时，旧事件合同仍强制填写具体模型。把请求的 Sol 写成实际
模型是在伪造证据；留空又无法推进生命周期，合法 replacement 结果也无法生成
回执。

同时，原任务的三次结果回收已经占用 attempt 1–3，replacement 丢失 final 后
没有独立恢复空间。若只增加文件名，还可能通过换目录重置次数，或把
replacement 伪装成 original，再创建第二个 replacement。

### 本版更新

- 平台不公开实际模型时，materialized 事件可写
  `model_id=null + model_verification_state=unverified + 绑定证据`。
- 请求模型保留在不可变计划中，绝不冒充已经观测到的实际模型。
- 模型验证状态和证据进入 journal 哈希；状态、完成结果和任务回执都保留
  unverified，不会在发布声明中变成 verified。
- replacement 丢失 final 时获得独立的 replacement recovery stage，与原任务
  的三次恢复分开。
- replacement 恢复绑定原 continuity receipt、replacement thread、逻辑来源、
  角色、checkpoint 和 input。
- recovery stage 从 journal 生命周期推导，不信任调用方自己填写的
  original/replacement。
- 收据只能写入 canonical receipts 目录；attempt 必须顺序、单次使用，第三次
  exhausted 后不能重新进入 running。
- replacement 可以恢复自身结果，但不能创建 replacement-of-replacement。

### 验证与限制

本版通过 33/33 PowerShell 解析、41/41 恢复协议专项断言、617/617 完整自测、
57/57 非法案例拒绝、8/8 JSON 解析和 Skill Creator 校验。独立 Reviewer 动态
复攻了请求模型冒充实际模型、缺证据、journal 篡改、换目录重置 attempt、第
四次恢复、stage 伪装和 replacement-of-replacement，最终 GREEN，
P0/P1/P2 均为 0。

Skill 不会让平台凭空暴露实际模型，也不修复平台 `systemError` 或 final 丢失；
它保证这些事实被诚实记录，并让恢复链不能被伪造。本版不宣称已证明生产环境
Token 节省。Windows 符号链接夹具因权限跳过；Linux/macOS 尚未动态验证。
