# Adaptive Agent Orchestrator v0.7.17

[简体中文](#简体中文) · [English](#english)

Release date: 2026-08-01

## 简体中文

### 解决的问题

长期审核进入同一里程碑的新 checkpoint 时，调用方可能只把“当前仍开放”的问题写入新的结果和处置文件，把上一轮已经解决、但仍必须在来源清单中守恒的条目漏掉。审核生命周期本身是合法的，旧选择链却无法安全消费新结果；手工覆盖旧文件又会破坏不可变审计链。

### 本版修复

- 增加一次性、全来源、非状态变更的累计清单 supersession 收据。
- 只从上一份已选清单机械补回遗漏条目，不改变来源、canonical ID、严重度、原文/哈希、状态或证据。
- 独立 inventory supersession 仍保持旧合同；若同一 run 同时存在 lifecycle correction，必须使用专用 cumulative correction 收据（schema 1.0 字段/事件），并由 schema 1.6 selection 同时绑定两份收据。旧字段、旧路径和旧事件不可混用。
- 重复、部分来源、跨来源搬运、降级、改文、旧路径、别名路径、过期 journal、分叉或第二次消费在写入前拒绝。

### 实际收益

修复后的 checkpoint 可以在不改旧结果、不重发审核、不伪造完成的前提下继续进入选择流程；历史问题不会因为换 checkpoint 而消失，开放 P0/P1 和主任务最终验收仍继续阻断完成。

真实 127-event run 已完成 lifecycle correction → cumulative correction → schema 1.6 selection → completion：

- journal 由 127 条追加到 129 条，原 127 条前缀 SHA 保持不变；
- traditional 累计 6 项，仅 `LY-TR-P1-09` 仍开放；
- adversarial 累计 4 项，`LY-ADV-CP17-P2-001` 为 deferred/open 但不阻断；
- completion 仍为 `BLOCKED`，只剩主任务未验收、缺 main-owner acceptance 和 `LY-TR-P1-09`；
- multi-divination 产品文件、提交和工作树未修改。

### 验证

- 固定 Skill 包 76/76 文件一致；
- PowerShell 解析 57、Milestone 273、Recovery 91、Materialization 45（负例 13）、Policy 15；
- Self 1014，intentional invalid 60，reference JSON 8，Skill Creator valid；
- 独立高价值外部变异 11/11 通过，P0/P1/P2=0/0/0；
- 真实 run 选择与 completion 采用通过，且按预期保持阻断。

### 边界

- 不修复平台 `systemError` 或缺失 final。
- 不判断或修复 multi-divination 业务问题，不修改其产品文件。
- 不宣称生产 Token 节省或业务准确率。
- Windows 符号链接夹具因权限限制跳过；Linux/macOS 未动态验证。
- 本地追加式哈希链不抵抗攻击者一致重写早期授权和后续历史；该威胁仍需要外部不可变锚点。

编排 policy 仍为 `0.7.6`。

## English

### The problem

When a long-lived review moved to a new checkpoint in the same milestone, a caller could write only the findings that were still open. Earlier source occurrences—already resolved or still required for conservation—were omitted. The lifecycle was valid, but the immutable selection could not consume the new result; editing old receipts would have broken the audit chain.

### Fix

- Add one all-source, one-time, non-state cumulative-inventory supersession receipt.
- Restore only omitted occurrences from the previously selected inventory, preserving source, canonical ID, severity, exact text/hash, status, and evidence.
- Keep standalone inventory supersession separate. If lifecycle correction is present, require the dedicated cumulative receipt and schema 1.6 selection to bind both receipts, with legacy fields, paths, and events rejected.
- Reject duplicate, partial, cross-source, downgraded, rewritten, stale, forked, or alias-path attempts before journal write.

### Benefit

A repaired checkpoint can enter selection without rewriting old results, resending reviews, or inventing completion. Findings do not disappear when the checkpoint changes, and open P0/P1 findings plus missing final main acceptance continue to block completion.

The real 127-event run completed lifecycle correction → cumulative correction → schema 1.6 selection → completion:

- the journal advanced from 127 to 129 events while the original 127-event prefix stayed byte-identical;
- the traditional source conserved six occurrences, with only `LY-TR-P1-09` still open;
- the adversarial source conserved four occurrences, with `LY-ADV-CP17-P2-001` deferred/open but non-blocking;
- completion remained `BLOCKED` only by missing main validation/acceptance and `LY-TR-P1-09`; and
- multi-divination product files, commit, and worktree were unchanged.

### Validation

- 76/76 fixed Skill files matched;
- 57 PowerShell parses, 273 milestone, 91 recovery, 45 materialization (13 negative), and 15 policy assertions;
- 1014 self-test assertions, 60 intentional invalid cases, 8 reference JSON parses, and Skill Creator validation;
- 11/11 high-value independent mutations passed with P0/P1/P2=0/0/0; and
- the real-run selection and completion adoption passed while preserving the expected block.

### Boundaries

- This release does not repair platform `systemError` or missing-final behavior.
- It does not judge or repair multi-divination product findings and did not modify its product files.
- It does not claim measured production Token savings or business accuracy.
- The Windows symbolic-link fixture was skipped; Linux/macOS were not dynamically validated.
- The local append-only hash chain does not resist coherent rewriting of early authorization and later history; that threat still needs an external immutable anchor.

The orchestration policy remains `0.7.6`.
