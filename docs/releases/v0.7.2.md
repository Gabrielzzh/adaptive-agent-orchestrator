# Adaptive Agent Orchestrator v0.7.2

Date: 2026-07-30
Channel: Stable

v0.7.2 turns long-running review from a final one-shot check into a durable,
auditable feedback loop. It also makes missing platform finals recoverable
without pretending that partial progress is a result.

## The pain this release addresses

Long projects often degrade into one expensive main agent doing all production,
followed by one reviewer at the end. That is fast when everything is correct,
but it hides domain gaps, delays dissent until rework is expensive, and lets one
review source accidentally stand in for another.

Platform task failures create another unsafe shortcut: a turn may report
`completed` while exposing commentary or tool activity but no final answer.
Treating that state as success loses the review; repeatedly creating new tasks
can duplicate work and break source continuity.

## What users gain

- **Persistent domain and dissent roles when justified.** Long-running research
  or Skill development can retain read-only domain and adversarial reviewers
  across named milestones. This is optional and never creates seats merely
  because roles exist.
- **A main agent that still works.** The main owner remains the only project
  writer, owns the global argument and integration, and answers every finding.
  Review workers do not modify the project or delegate further.
- **Finding-by-finding accountability.** Each source report is captured and
  hash-bound. The main owner records `adopted`, `partially_adopted`, `rejected`,
  or `deferred` for every finding, with rationale and evidence.
- **Independent sources stay independent.** Overlapping findings may share a
  canonical issue, but each source keeps its own evidence and disposition
  receipt. One reviewer's PASS cannot replace another reviewer's obligation.
- **Blocking findings cannot be downgraded away.** Durable review always blocks
  unresolved P0/P1 findings. Disposition must exact-match the source finding ID,
  original severity, text, and text hash. P2 may be deferred only with a reason.
- **Missing finals fail closed.** A completed turn without a final becomes
  `result_pending`. Visible commentary and tool activity may be hash-bound as
  recovery evidence, but never count as the result or satisfy completion.
- **Bounded same-source recovery.** The original role and thread get at most
  three minimal result-recovery attempts for the same source, checkpoint, and
  input. Scope, role, thread, or checkpoint changes are rejected.
- **Authorized replacement with continuity.** Only a verified 3/3 recovery
  chain can make a source replacement-eligible. A replacement must bind the
  original logical source, role contract, checkpoint, input, recovery-chain
  hash, controller authorization, and its own task identity. It reports itself
  as a replacement and cannot claim that the original task passed.
- **Honest adoption of older tasks.** If an old durable task never exposed
  machine source IDs or original hashes, the controller captures the real role
  text, checkpoint/input material, four observed turn records, and authorization
  text, then lists unavailable fields as unknown. The Skill does not invent
  historical evidence.
- **Platform-bound model launch.** Concrete worker models still require the
  deterministic resolver and current platform binding. Terra remains
  explicit-request-only; missing or unavailable routes do not silently inherit
  the main agent's model.

Consumer-facing output remains result-only. Internal commentary, tool traces,
and reviewer debate are not copied into ordinary delivery unless an unresolved
risk or user decision must be disclosed.

## Limits

- This Skill does not fix platform `systemError`, missing-final, or task-hosting
  failures. It prevents those states from being misreported as success and
  preserves verifiable recovery and replacement continuity.
- The release does not claim measured production Token savings.
- The Windows symbolic-link fixture was skipped because this environment did
  not permit link creation. The Windows Junction/reparse-point fixture remains
  covered.
- Windows 10 with PowerShell 7.6.3 is dynamically validated. Linux and macOS
  behavior has not been dynamically validated.

## 中文说明

v0.7.2 解决两个长期项目中的实际痛点：主 Agent 包办全部生产、最后才进行一次
审查；以及平台任务显示完成却没有最终回答时，结果容易丢失或被错误当作成功。

### 用户获得什么

- **按需保留长期领域专家和反方角色：** 适用于跨多个里程碑的研究或 Skill
  研发，不为凑席位创建角色。
- **主 Agent 继续生产：** 主 Agent 是唯一项目 Writer，负责主线、逐项回应、
  整合和最终验收；领域与反方角色保持只读，不能继续派生 Worker。
- **逐条处理审核意见：** 每份完整报告都以哈希绑定；每项发现必须记录采纳、
  部分采纳、拒绝或延期，并附理由与证据。
- **多个来源不能互相替代：** 重叠问题可以归为同一 canonical issue，但仍
  保留各自来源、回执和复审义务；一个角色 PASS 不能替代另一个。
- **P0/P1 不能被降级逃逸：** durable review 固定阻断未解决 P0/P1；处置
  必须精确匹配原 finding ID、severity、text 与 text hash。P2 只有说明理由
  才能延期。
- **缺失 final 时安全阻断：** `completed` 但无 final 的任务进入
  `result_pending`。可见 commentary 或工具活动只作为哈希证据，绝不冒充
  最终结果。
- **同源最多三次回收：** 只允许同一角色、线程、来源、checkpoint 和 input
  进行最多三次最小结果回收，禁止借恢复扩大范围。
- **替代角色必须保持连续性：** 只有完整 3/3 回收链和主控授权才能创建
  replacement；替代结果必须声明 replacement 身份，不能声称原任务 PASS，
  也不能替代其他来源。
- **旧任务可以诚实接入：** 对平台从未提供的旧 source ID 或 hash，保存真实
  可见材料并明确列为 unknown，不补造历史身份。
- **模型启动仍受平台绑定：** 具体模型必须经过确定性 resolver 和当前平台
  binding；Terra 仍只能由用户明确指定，不能因“便宜”自动启用。

消费者只看到最终结果。内部争论、commentary 和工具轨迹不会进入普通输出，
除非存在必须披露的未解决风险或用户决策。

### 验证与限制

本版通过 33/33 脚本解析、30/30 恢复协议专项断言、601/601 全量断言、
57/57 非法案例拒绝、8 个严格 JSON 解析和 Skill Creator 校验。同一独立
审核角色对两项真实绕过完成动态复攻，最终结论为 GREEN，P0/P1/P2 均为 0。

Skill 不修复平台自身的 `systemError` 或 final 丢失；它保证这些状态不会被
伪装成成功，并让恢复和替代过程可核验。本版不宣称已证明生产环境 Token
节省。Windows 符号链接夹具因权限被跳过；Linux/macOS 尚未动态验证。
