# v0.7.19 — Goal-first user experience

This release adds a plain-language entry layer without changing the durable
orchestration protocol. Users can describe the outcome they want; the Skill
handles a simple task directly and proposes separation only when it materially
helps a complex goal.

## What changed

- The Chinese quick start begins with ordinary goal descriptions instead of a
  Skill command.
- Skill metadata now triggers from projects and potentially complex outcomes,
  then requires goal understanding before any delegation decision.
- Simple, narrow, or strongly sequential work stays with the responsible Agent.
- When separation helps, the first response says only what work would be split,
  why that helps, and how many confirmations are needed. Internal execution and
  evidence details remain hidden unless the user asks or a decision requires
  them.
- User-facing `openai.yaml` metadata describes outcomes rather than assuming
  orchestration knowledge.

## Boundaries

- No lifecycle, recovery, receipt, hash, ownership, worktree, review, or
  completion-gate behavior changed.
- This release does not install product-specific workflows or change
  multi-divination.
- The existing internal supervision and fail-closed controls remain in force.
