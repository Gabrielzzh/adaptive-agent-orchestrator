# Adaptive Agent Orchestrator v0.7.14

[简体中文](#简体中文) · [English](#english)

Release date: 2026-07-31

## 简体中文

### 解决的问题

长期审核不是“一次创建、永远可用”。真实研发中出现了三个连续痛点：

1. 已合法接替原审核员的 replacement 只获得单个 checkpoint 的权限，到了
   下一个 checkpoint 无法继续履行同一审核职责。
2. 当前两位长期审核员后来都无法继续提供独立结果：一位读入了不该共享的
   历史，另一位已耗尽恢复次数。旧任务不能复用，也不能继续套娃创建
   replacement-of-replacement。
3. 一个 fresh 任务实际上已经创建成功，但调用方在 `materializing` 阶段提前
   写入了它的 ID。旧状态机随后把紧邻的 `materialized` 当成重复使用，既不能
   接回已存在任务，也不能安全重建。

这些路径都安全地保持阻断，但会让长期研发停在控制层。

### 本版修复

- 新增 replacement 席位的 checkpoint 推进：只允许同一 run、来源、角色和
  thread 在主控授权下追加一次新 checkpoint；旧 continuity 不被覆盖，也不
  创建 replacement-of-replacement。
- 新增 active-mid-run source rotation：把当前 run 的全部开放问题逐条导出到
  一个 fresh successor，再建立两个全新的长期只读、无委派审核席位。旧
  original 和 replacement 均不得复用。
- 严格保留每条问题的来源、严重度、原文及哈希、canonical ID、checkpoint、
  input、角色合同与已消耗 attempt。漏项、降级、跨来源合并、重复导出或分叉
  都会在写入前拒绝。
- 允许非常窄的相邻物化恢复：只有同一节点紧邻的
  `materializing -> materialized` 可以沿用前一事件中的同一 thread ID，并
  且必须同时具备启动预留、任务列表唯一匹配和精确
  `MATERIALIZED_WAITING_FOR_CONTINUITY` 握手。
- 同时存在 `thread_id`、`id`、`threadId` 时必须完全一致；空值、大小写差异、
  跨节点别名冲突都会拒绝，不能择一采用或盲目重建任务。

### 实际收益

- replacement 可以在不扩大权限的前提下继续下一轮复审；
- 两位长期审核员都不可用时，可以一次性换成两位全新的独立审核员；
- 所有旧问题一个不少地带到新 run，不能因换人消失或降级；
- 已经创建成功的任务不会因一次相邻状态记录错误而被重复创建；
- 主 Agent 仍是唯一 Writer，审核员保持只读、无下级 Agent；
- 任何开放 P0/P1、缺失正式结果或缺少主任务验收，仍会阻断完成。

### 独立验收与真实采用

- replacement checkpoint roll-forward 已在真实长期审核 run 中通过。
- source rotation 固定候选由同一独立验收角色动态复攻，结论 GREEN，
  P0/P1/P2=0；真实 run 将 7/7 条开放 P1 原样继承到两个 fresh 审核席位。
- 物化连续性候选通过 45 项专项断言（含 13 个非法案例），独立动态复攻
  17/17 通过，P0/P1/P2=0。
- 真实采用只接回已经存在的 traditional 任务，再创建一个 adversarial 任务；
  两个 fresh source 均合法进入审核，没有重复创建。
- 两个任务遇到平台 final 缺失后，均通过各自同线程恢复取得正式结果，并生成
  source-specific result、disposition 和完整生命周期。
- completion 最终仍因 multi-divination 自身新增 P0、7 条开放 P1 和缺少
  main acceptance 保持 `BLOCKED`。这是预期的安全结果；没有发现新的
  Orchestrator P0/P1。

### 验证

- 45 项物化连续性断言，其中 13 个非法案例正确拒绝；
- 91 项恢复协议断言；
- 106 项 durable milestone/revision/successor 断言；
- 840 项完整自测，59 个非法案例正确拒绝；
- 8 个 reference JSON 文件严格解析；
- Skill Creator 校验；
- 固定安装包、功能提交与安装副本 72/72 文件核对；
- source rotation 与 materialization continuity 均独立 GREEN；
- 真实 fresh 双来源 formal result/disposition/lifecycle 链通过。

### 边界

- 本版不修复平台 `systemError` 或 final 丢失本身。
- 本版不判断或修复 multi-divination 的业务 P0，也没有修改其产品文件。
- 本版不声明生产环境 Token 节省或业务准确率。
- source rotation 只迁移审核义务与席位，不迁移业务产物。
- replacement-of-replacement 仍然禁止；旧审核任务不能在 rotation 后复用。
- 本地追加式哈希链不能抵抗攻击者一致重写早期授权和全部后续历史；该威胁
  需要外部不可变锚点。
- Windows 符号链接夹具因权限限制跳过；Linux/macOS 未动态验证。

编排 policy 仍为 `0.7.6`。v0.7.14 是该 policy 下的控制补丁，不要求改写
内部一致的现有 plan、run 或 journal。

## English

### The problem

Long-lived review is not a one-time task creation. Real adoption exposed three
consecutive fail-closed blocks:

1. A valid replacement reviewer was authorized for one checkpoint but had no
   formal path to continue the same logical review responsibility at the next
   checkpoint.
2. Both current durable reviewers later became unusable for independent review:
   one had contaminated context and the other exhausted bounded recovery. Old
   tasks could not be reused, and replacement-of-replacement remained forbidden.
3. A fresh task had actually materialized, but its ID was recorded one lifecycle
   step early on `materializing`. The adjacent `materialized` event was then
   rejected as task reuse, while blind recreation was also forbidden.

The controls failed closed correctly, but durable development could not proceed.

### Fixes

- Add checkpoint roll-forward for a replacement seat. A controller-authorized
  append may continue only the same run, logical source, role, and task. It does
  not overwrite continuity or create a replacement-of-replacement.
- Add active-mid-run source rotation. Every open source occurrence is exported
  into one fresh successor run with two new read-only, nondelegating reviewer
  seats. Neither original nor replacement tasks may be reused.
- Preserve each occurrence's source, severity, exact text/hash, canonical ID,
  checkpoint, input, role contract, and consumed attempts. Omission, downgrade,
  cross-source merge, replay, or fork fails before journal write.
- Permit one narrow adjacent materialization recovery. Only the same node's
  immediate `materializing -> materialized` transition may reuse the exact
  prior thread ID, with an activation reservation, unique task-list match, and
  exact `MATERIALIZED_WAITING_FOR_CONTINUITY` handshake.
- Require concurrently present `thread_id`, `id`, and `threadId` fields to match
  exactly. Empty values, case-only differences, and cross-node aliases fail
  closed instead of selecting one identity or recreating a task.

### Benefits

- a replacement can continue later review without expanding its authority;
- two unusable reviewers can be rotated once into two genuinely fresh,
  independent reviewers;
- every existing problem survives rotation without disappearance or downgrade;
- an already-created task is not duplicated after an adjacent sequencing error;
- the main agent remains the only writer, while reviewers remain read-only and
  cannot delegate; and
- any open P0/P1, missing formal result, or missing main acceptance still blocks
  completion.

### Independent acceptance and real adoption

- Replacement checkpoint roll-forward passed in the real durable-review run.
- The source-rotation fixed candidate received independent dynamic GREEN with
  P0=0/P1=0/P2=0. Real adoption preserved 7/7 open P1 occurrences in two fresh
  reviewer seats.
- Materialization continuity passed 45 focused assertions including 13 invalid
  cases, plus an independent 17/17 dynamic re-attack with P0=0/P1=0/P2=0.
- Real adoption reconciled the already-created traditional task and created only
  one additional adversarial task. Both fresh sources entered review without
  duplication.
- After platform missing-final behavior, each task recovered a formal result on
  its own thread and produced source-specific result, disposition, and complete
  lifecycle evidence.
- Completion remained correctly `BLOCKED` by a multi-divination product P0,
  seven open P1 occurrences, and missing main acceptance. No new Orchestrator
  P0/P1 was found.

### Validation

- 53 PowerShell scripts parsed;
- 45 materialization-continuity assertions, including 13 rejected invalid cases;
- 91 recovery-protocol assertions;
- 106 durable milestone/revision/successor assertions;
- 840 full self-test assertions and 59 rejected invalid cases;
- 8 strict reference JSON parses;
- Skill Creator validation;
- fixed package, functional commit, and installed Skill checked across 72/72
  files;
- independent GREEN for source rotation and materialization continuity; and
- real fresh two-source formal result/disposition/lifecycle passed.

### Boundaries

- This release does not repair platform `systemError` or missing-final behavior.
- It does not judge or fix the multi-divination product P0 and did not modify
  multi-divination product files.
- It does not claim measured production Token savings or business accuracy.
- Source rotation carries review obligations and seats, not business artifacts.
- Replacement-of-replacement remains forbidden, and old reviewer tasks cannot
  be reused after rotation.
- The local append-only hash chain does not resist coherent rewriting of early
  authorization and all later history; that threat requires an external
  immutable anchor.
- The Windows symbolic-link fixture was skipped; Linux/macOS were not
  dynamically validated.

The orchestration policy remains `0.7.6`. v0.7.14 is a control patch under that
policy and does not require rewriting a consistent existing plan, run, or
journal.
