# Adaptive Agent Orchestrator v0.7.1

Date: 2026-07-28

v0.7.1 corrects the durable Codex task lifecycle introduced in v0.7.0.

## Changes

- An explicit request for a visible or long-lived Codex thread is no longer
  allowed to fall back silently to a native subagent.
- Independent, bounded, checkable work that can use smaller context or a
  lower-cost model now proactively recommends a durable task. Because that task
  is user-owned and visible, creation still requires an explicit request or
  confirmation.
- `Resolve-CodexExecutionSurface.ps1` distinguishes main-agent,
  native-subagent, durable-local, and durable-worktree execution.
- `Test-CodexWorktreePreflight.ps1` verifies Git repository state and a usable
  `HEAD` before any worktree creation request. Read-only work can use a saved
  local project; an isolated writer stops when no safe worktree baseline exists.
- A queued worktree `clientThreadId` is now `setup_pending`, not a materialized
  task. If no real task appears after bounded reconciliation, the state becomes
  `setup_failed_or_unresolved` and never authorizes blind retry.
- Model routing verifies the destination's exposed models, does not silently
  inherit the main agent's model, and returns unavailable-model work to the main
  agent or a user-authorized substitute.
- `New-OrchestrationTaskReceipt.ps1` records one immutable run outcome:
  `completed`, `fallback-main`, `blocked`, or `cancelled`, with evidence and
  failure-specific fallback behavior.

## Safety boundaries

- Workers cannot create other Workers or become orchestrators.
- The main agent retains integration, acceptance, external actions, and final
  delivery.
- One writer owns each write scope. Local durable tasks with overlapping write
  scopes are rejected or moved to isolated worktrees.
- A `clientThreadId` cannot be passed to `read_thread` or `wait_threads`.
- Model escalation and Ultra retain their existing user-confirmation gates.
