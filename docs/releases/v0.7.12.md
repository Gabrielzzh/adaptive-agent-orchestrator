# Adaptive Agent Orchestrator v0.7.12

[简体中文](#简体中文) · [English](#english)

Release date: 2026-07-31

## 简体中文

### 解决的问题

长期只读审核角色会跨多个里程碑持续工作。进入后续里程碑时，控制链可以通过
正式 activation 选中该来源的新 result 与 disposition，而无需伪造新的节点
生命周期。

此前这里存在一个安全阻塞：当同一来源在该里程碑的新 checkpoint 再次丢失
final 时，恢复 cycle 可以合法生成，但 `adopted -> result_pending` 只检查
最近一次节点生命周期。该旧链仍属于上一里程碑，因此恢复入口拒绝继续。

系统没有误放行，但原长期审核角色无法对当前里程碑做同线程结果回收。

### 本版收益

- 保持普通 `adopted` 为终态，不开放通用重启。
- 只有未使用的 schema 1.2 attempt-1 cycle 绑定不同的新 checkpoint/input
  时，才考虑恢复入口。
- 若最近节点生命周期属于旧里程碑，入口会完整验证当前 active milestone 的
  同一来源、角色、thread、result、disposition、activation receipt 与
  activation journal event。
- 新 `result_pending` 事件明确绑定旧 adopted sequence/hash、当前
  result/disposition 路径及内部哈希、activation 路径/哈希/事件和新
  checkpoint/input。
- 旧里程碑、未选结果、跨来源/角色/thread、同 checkpoint 重放、已使用
  cycle、attempt 2/3 直接开启，以及 selection、activation、checkpoint 或
  input 篡改都会在写 journal 前拒绝。

### 真实采用验证

修复后的安装版在 multi-divination 真实 39-event 长期审核 run 中完成：

- 原 39 条 journal 前缀 SHA-256 保持
  `aeb0bccd788239d1c5ce579a34e927995198f2ad7b62547ba8419a51096b725d`；
- traditional source 以当前 Group2 选择链进入
  `adopted -> result_pending -> running`；
- `result_pending` 精确绑定 Group2 result
  `fce1c8180be5e37173d3fa45b864b75b4dc0bd16073c84ff9e92b73edc07eced`、
  disposition
  `eda01ccdf73fd546d1a2b870c9edf40fd3855c079be55271a1af5d5b90920936`
  和 activation
  `2dc7bd36e331ad0a950028088e7e8e1e97c32685edff169c09b25c355e0601c6`；
- 新 checkpoint/input 分别绑定
  `b2b242c3794ff6822c231a7833838d012813b2277c49b94195242ef1258e2c62`
  与
  `0e9c211bfca8f085550e7fc596fbf5b8f7544f8900a0d972e109edceb67e248f`；
- 原 traditional 长期任务随后返回正式 final，证明同线程恢复链可用。

该 final 的 `FAIL` 表示领域审查尚未完成，且没有新增产品 finding；它不是
Orchestrator 回归，也没有被冒充为业务 PASS。后续 final 缺失仍受既有三次
有界 cycle 约束；attempt-3 receipt 产生后，该 cycle 已耗尽，不允许再发送
第 4 次请求。继续阻断或另行授权 replacement 不属于本版新增功能。

### 边界

- 本版不修复平台 `systemError` 或 final 丢失本身。
- 本版不把不完整领域审查写成产品 PASS，也不判断 multi-divination 的业务
  正确性。
- 本版不声明生产环境 Token 节省或业务准确率。
- 本版没有修改 multi-divination 产品文件。
- 普通 `adopted` 仍是终态；没有完整当前里程碑绑定时不能重开。
- attempt-3 recovery receipt 表示本 cycle 已耗尽，不是额外发送许可。
- 本地追加式哈希链不能抵抗攻击者一致重写 activation、selection 与全部后续
  历史；该威胁需要外部不可变锚点。
- Windows 符号链接夹具因权限限制跳过；Linux/macOS 未动态验证。

编排 policy 仍为 `0.7.6`。v0.7.12 是该 policy 下的控制补丁，不要求改写
内部一致的现有 plan、run 或 journal。

## English

### The problem

Long-lived read-only review sources continue across declared milestones. A
later milestone can formally select a fresh source-specific result and
disposition through activation without inventing a new node lifecycle.

That exposed a fail-closed block. If the same source lost its final at another
checkpoint under the active milestone, a valid recovery cycle could be
created, but `adopted -> result_pending` checked only the latest node
lifecycle. That older chain still belonged to the preceding milestone, so the
recovery entry was rejected.

No stale evidence was accepted, but the original durable source could not
recover its current-milestone result on the same thread.

### Benefits

- Ordinary `adopted` remains terminal; this is not a general restart path.
- Recovery is considered only for an unused schema 1.2 attempt-1 cycle bound
  to a different new checkpoint/input.
- When the latest node lifecycle belongs to an older milestone, the gate fully
  verifies the active milestone's same source, role, thread, result,
  disposition, activation receipt, and activation journal event.
- The new `result_pending` event binds the preceding adopted sequence/hash,
  active result/disposition paths and internal hashes, activation path/hash/
  event, and new checkpoint/input.
- Old milestones, unselected results, cross-source/role/thread substitution,
  same-checkpoint replay, consumed cycles, direct attempt 2/3 entry, and
  selection/activation/checkpoint/input tampering fail before journal write.

### Real adoption

The installed fix ran against the real 39-event multi-divination durable-review
run:

- the original 39-event journal prefix retained SHA-256
  `aeb0bccd788239d1c5ce579a34e927995198f2ad7b62547ba8419a51096b725d`;
- the traditional source entered
  `adopted -> result_pending -> running` under the current Group2 selection;
- `result_pending` bound the exact Group2 result
  `fce1c8180be5e37173d3fa45b864b75b4dc0bd16073c84ff9e92b73edc07eced`,
  disposition
  `eda01ccdf73fd546d1a2b870c9edf40fd3855c079be55271a1af5d5b90920936`,
  and activation
  `2dc7bd36e331ad0a950028088e7e8e1e97c32685edff169c09b25c355e0601c6`;
- the new checkpoint and input were bound to
  `b2b242c3794ff6822c231a7833838d012813b2277c49b94195242ef1258e2c62`
  and
  `0e9c211bfca8f085550e7fc596fbf5b8f7544f8900a0d972e109edceb67e248f`;
  and
- the original traditional durable task then returned a formal final, proving
  that the same-thread recovery path was usable.

That final's `FAIL` meant the domain review itself was incomplete and reported
no new product finding. It was not an Orchestrator regression and was not
presented as a business PASS. Later missing-final observations remain governed
by the existing three-attempt cycle. Once an attempt-3 receipt is created, that
cycle is exhausted and cannot authorize a fourth send. Remaining blocked or
using a separately authorized replacement is not new functionality here.

### Validation

- 48 PowerShell scripts parsed;
- 66 focused recovery-protocol assertions;
- 102 durable-milestone/revision assertions;
- 810 full self-test assertions and 59 rejected invalid cases;
- 8 strict reference JSON parses;
- Skill Creator validation;
- the same independent Noether dynamically re-attacked the fixed
  commit/package and returned GREEN with P0=0, P1=0, and P2=0;
- 19/19 adjacent attacks failed before journal write, with unchanged journal
  length and SHA-256;
- fixed ZIP, commit tree, and installed Skill matched 67/67 files by SHA-256;
  and
- the real 39-event recovery entry and same-thread final retrieval passed.

### Boundaries

- This release does not repair platform `systemError` or missing-final
  behavior.
- It does not turn an incomplete domain review into product success or judge
  multi-divination business correctness.
- It does not claim measured production Token savings or business accuracy.
- It did not modify multi-divination product files.
- Ordinary `adopted` remains terminal without a complete current-milestone
  binding.
- An attempt-3 recovery receipt exhausts its cycle; it is not another send
  authorization.
- The local append-only hash chain does not resist coherent rewriting of the
  activation, selection, and all later retained history. That threat requires
  an external immutable anchor.
- The Windows symbolic-link fixture was skipped; Linux/macOS were not
  dynamically validated.

The orchestration policy remains `0.7.6`. v0.7.12 is a control patch under that
policy and does not require rewriting a consistent existing plan, run, or
journal.
