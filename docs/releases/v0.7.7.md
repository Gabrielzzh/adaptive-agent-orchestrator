# Adaptive Agent Orchestrator v0.7.7

[简体中文](#简体中文) · [English](#english)

Release date: 2026-07-30

## 简体中文

### 解决的问题

Codex 当前 `read_thread` 原始 JSON 使用 `thread.id`。v0.7.6 的 capture
解析器只接受历史字段 `thread.threadId` 或顶层 `threadId`，因此真实长期
审核任务即使已经返回合法 final，也无法生成 result receipt。

本次真实采用还暴露出一个相邻问题：只有一条 finding 时，PowerShell 会把
数组解包为标量，schema 1.2 result receipt 会在读取 `.Count` 时失败。

### 本版收益

- 原始 `read_thread` JSON 可以直接进入 read、progress 和 result-receipt
  验证，不要求调用方转换或手改。
- 两种历史身份字段继续兼容。
- 两个或三个身份字段同时存在时必须逐值完全一致；冲突、空值及仅大小写不同
  都会在写入 receipt 前 fail closed。
- 单条 legacy finding 会稳定保存为一元素 JSON 数组。
- 两份真实 capture 已分别生成 schema 1.3 result 与 disposition 收据。

### 版本策略

包版本升级为 `v0.7.7`，编排 policy 仍为 `0.7.6`。这是兼容性解析修复，
没有改变 plan、run、journal 或完成门合同，因此现有 `0.7.6` run 不需要
额外 policy activation。

### 验证

- 42 个 PowerShell 脚本解析；
- 13 项 capture 兼容专项断言；
- 724 项完整自测，59 个非法案例正确拒绝；
- 8 个 reference JSON 文件严格解析；
- Skill Creator 校验；
- 同一独立 Noether 角色完成 27/27 动态复攻，P0/P1/P2 均为 0；
- 两份真实 capture SHA 与现场证据一致，并成功生成独立 result/disposition。

### 边界

- 本版不修复平台 `systemError` 或缺失 final。
- 本版不允许事后补写已经发生的 Worker 生命周期；launch、running 与
  completion 仍必须按真实时序记录。
- 本版不声明生产环境 Token 节省。
- Windows 符号链接夹具因权限限制跳过；Linux/macOS 未动态验证。

## English

### The problem

Current Codex `read_thread` JSON identifies a task with `thread.id`. The v0.7.6
capture parser accepted only the historical `thread.threadId` or top-level
`threadId`, so a valid final from a real durable reviewer could not produce a
result receipt.

The same adoption run exposed a neighboring bug: PowerShell scalarized a
single finding, causing schema 1.2 receipt generation to fail on `.Count`.

### Benefits

- Raw `read_thread` JSON now enters read, progress, and result-receipt
  validation without caller-side conversion.
- Both historical identity shapes remain compatible.
- When two or three identity fields coexist, every value must match exactly.
  Conflicts, empty values, and case-only differences fail before receipt
  creation.
- One legacy finding remains a one-element JSON array.
- Two real captures produced separate schema 1.3 result and disposition
  receipts.

### Versioning

The package version is `v0.7.7`, while the orchestration policy remains
`0.7.6`. This compatibility patch does not change plan, run, journal, or
completion contracts, so existing `0.7.6` runs need no policy activation.

### Validation

- 42 PowerShell scripts parsed;
- 13 focused capture-compatibility assertions;
- 724 full self-test assertions and 59 rejected invalid cases;
- 8 strict reference JSON parses;
- Skill Creator validation;
- 27/27 dynamic attacks by the same independent Noether reviewer, with
  P0/P1/P2 all zero;
- two real captures matched their recorded hashes and generated independent
  result/disposition receipts.

### Boundaries

- This release does not repair platform `systemError` or a missing final.
- It does not permit retroactive Worker lifecycle entries; launch, running, and
  completion must still follow real event order.
- It does not claim measured production Token savings.
- The Windows symbolic-link fixture was skipped; Linux/macOS were not
  dynamically validated.
