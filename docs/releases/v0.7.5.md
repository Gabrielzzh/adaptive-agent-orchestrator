# Adaptive Agent Orchestrator v0.7.5

[简体中文](#简体中文) · [English](#english)

Release date: 2026-07-30

## 简体中文

### 解决的问题

长期领域审核和反方审核会跨越多个里程碑。此前，一个不可变计划只能为每个
来源固定一条 disposition 路径：即使同一审核角色已经针对新 checkpoint
生成了合法 result 和 disposition，完成门仍可能读取旧里程碑的收据，重新
报告已经关闭的问题。用户只能在“手改不可变计划”和“继续被旧问题阻断”
之间二选一。

v0.7.5 为同一 durable review run 增加追加式里程碑激活。它不修改旧 plan、
run metadata 或 journal，而是明确选择下一条已声明的里程碑及其精确证据链。

### 本版收益

- 每个激活绑定 plan、run、journal head、前一里程碑、当前 milestone ID，
  以及每个必需来源的 thread、checkpoint、result/disposition 路径和哈希。
- 完成门只读取最新一条合法激活，不按文件时间或“最新文件名”猜测。
- result 与 disposition 都绑定 milestone 和 checkpoint，跨来源、跨
  checkpoint、跨 run 重放会被拒绝。
- 每个新里程碑都要求主 Agent 重新验收；旧 `validated` 状态不能批准新结果。
- 验收身份、验收 key 和证据路径/哈希在激活时预先绑定，不能只改写并重签
  acceptance 链尾来替换验收者或证据。
- 多个审核来源继续独立；一个来源不能替代另一个，未解决 P0/P1 始终阻断。
- 多个 typed evidence pointer 被 CLI 错误拼成一个逗号字符串时，在写入
  journal 前直接拒绝；普通 observation 文本中的逗号不受影响。

### 使用原则

里程碑激活是 append-only、顺序且一次性的。修复后的下一轮复审应使用计划中
下一条已声明的 milestone；不能重复激活同一 milestone，也不能静默选择某个
更新时间较新的 receipt。

### 验证

- 38 个 PowerShell 脚本解析；
- 19 项 durable milestone 专项断言；
- 15 项 run-policy activation 专项断言；
- 45 项 recovery protocol 专项断言；
- 704 项完整自测断言；
- 59 个故意构造的非法案例正确拒绝；
- 8 个 reference JSON 文件严格解析；
- Skill Creator 校验；
- 同一独立 Noether 审核角色动态复攻，最终 P0/P1/P2 均为 0；额外攻击集
  30/30 通过。

### 边界

- 本 Skill 不修复平台 `systemError` 或 final 丢失，只防止这些状态被当成
  成功并保护恢复/替代证据。
- 本版不迁移业务产物，也没有修改 multi-divination 项目。
- 本版不声称已经证明生产环境 Token 节省。
- 本地哈希链能发现链内篡改，但若攻击者能改写最早 activation 及全部后续
  journal，仍需要外部保存的 head/hash 才能抵抗完整历史重写。
- Windows 符号链接夹具因权限限制跳过；Linux/macOS 未动态验证。

## English

### The problem

Durable domain and dissent reviews span multiple milestones. Previously, an
immutable plan could name only one disposition path per source. Even after the
same reviewers produced valid result and disposition receipts for a newer
checkpoint, completion could keep reading the old milestone and report already
closed findings again. The only apparent choices were mutating the immutable
plan or remaining blocked by stale evidence.

v0.7.5 adds append-only milestone activation inside the same durable review
run. It preserves the old plan, run metadata, and journal while selecting the
next declared milestone and its exact evidence chain.

### Benefits

- Activation binds the plan, run, journal head, previous milestone, current
  milestone ID, and each required source's thread, checkpoint, result and
  disposition paths, and hashes.
- Completion consumes only the latest valid activation; it never guesses from
  file timestamps or a newest-looking filename.
- Result and disposition receipts bind milestone and checkpoint, rejecting
  cross-source, cross-checkpoint, and cross-run replay.
- Every activated milestone needs a fresh main-owner acceptance. An earlier
  `validated` state cannot approve later evidence.
- Acceptance identity, key, and evidence path/hash are pre-bound at activation,
  preventing coherent re-signing of only the acceptance tail.
- Independent sources remain separate and unresolved P0/P1 findings remain
  completion blockers.
- CLI-joined typed evidence pointers are rejected before journal write while
  ordinary commas in observation text remain valid.

### Operating rule

Milestone activation is append-only, sequential, and single-use. A later
re-review must use the next milestone declared by the immutable plan. The same
milestone cannot be reactivated, and receipt selection never relies on mtime.

### Validation

- all 38 PowerShell scripts parsed;
- 19 durable-milestone assertions;
- 15 run-policy activation assertions;
- 45 recovery-protocol assertions;
- 704 full self-test assertions;
- 59 intentionally invalid cases rejected;
- all 8 reference JSON files strictly parsed;
- Skill Creator validation;
- dynamic re-attack by the same independent Noether reviewer ended with
  P0=0, P1=0, and P2=0; an additional 30/30 attack set passed.

### Boundaries

- The Skill does not repair platform `systemError` or missing-final behavior.
- It does not migrate business artifacts or modify the multi-divination
  project.
- It does not claim measured production Token savings.
- The local hash chain detects in-chain tampering, but resisting an attacker
  who can rewrite the earliest activation and every later journal entry still
  requires an externally retained head/hash anchor.
- The Windows symbolic-link fixture was skipped; Linux and macOS were not
  dynamically validated.
