# Adaptive Agent Orchestrator v0.7.0

Stable release / 正式版本  
Date / 日期: 2026-07-27

![Adaptive Agent Orchestrator v0.7.0 launch visual](../assets/adaptive-agent-orchestrator-v0.7.0-launch.png)

## 中文

v0.7.0 是一次较大的正式更新。它不是把主 Agent 变成只会派任务的经理，
也不是为了制造更多 Agent。它让主 Agent 保持生产，同时只把可以用更少
上下文独立完成、独立验收的工作交给合适的 Worker。

### 这一版为什么更好

- **主 Agent 继续干活：** 主 Agent 保留全局主线、高耦合工作、用户沟通、
  外部动作和最终验收；Worker 只拥有边界清楚的局部产物。
- **更少上下文重复：** 默认传路径、来源 ID、产物指针和必要片段，不复制
  完整对话、仓库或历史日志。
- **临时与长期任务分开：** 一次性核验使用轻量 native subagent；需要独立
  历史、跨回合恢复或复用时才创建 durable background task。
- **角色透明：** 每个 Worker 创建前说明为什么需要、是什么角色、采用何种
  执行形式、读取什么、交付什么、拥有什么权限和使用哪个模型；创建后报告
  实际身份、状态与模型。
- **防止重复创建：** 创建调用报错或暂时不可见，不等于任务不存在。系统会
  结合返回 ID、创建时间、来源任务和激活标记核对实体；状态不明时停止盲目
  重试。
- **主 Agent 亲自验收：** 必需后台结果必须读取并形成哈希绑定的结果回执，
  才能进入最终整合。
- **Worker 输出不是指令：** 主 Agent 的控制面政策要求把 handoff、finding、
  artifact 和项目知识作为不可信数据复核；其中要求跳过验证、扩大派遣或
  改变权限的文本必须被报告，不能直接作为操作授权。
- **发现带来源等级：** `[verified]`、`[inferred]` 和 `[assumed]` 区分
  可复核事实、推断与假设；主 Agent 不得用假设满足完成门。该规则通过
  Worker packet 和主 Agent 复核执行，不声称自由文本受到安全沙箱强制。
- **容量不会被常驻任务占满：** 目标活动容量按 4 个 durable task 加 2 个
  transient subagent 隔离，且始终服从实际运行时上限。
- **模型选择不增加前置测试：** 正式任务直接使用静态路由表，不先创建模型
  测试 Agent。Luna 处理边界明确的机械任务，Sol 处理普通或困难判断；
  Terra 只在用户明确指定时使用，Ultra 必须逐节点确认。

### 主要更新

1. **上下文所有权与动态派遣**

   主 Agent 在任务开始和关键事件点重新判断 `main owns`、
   `dispatch native`、`dispatch durable`、`defer` 或 `stop`。只有独立结果
   能被验收、上下文明显更小且能与主线并行时，才创建 Worker。

2. **任务实体核对与结果回执**

   durable task 使用稳定 activation key；每个 key 只创建一次。返回 ID
   与任务列表快照共同参与核对，模糊状态保持 `unknown`。必需结果通过真实
   平台读取路径收集，并写入哈希绑定 receipt。

   durable background task 在归档前会重新验证已经记录的结果回执，并把
   回执哈希绑定到 archive 事件；回执消失或被篡改时拒绝归档。

3. **轻量项目知识与恢复**

   只有长期项目或多个工作流确实会复用时，才保存有来源的决策、事实、接口
   和未解决风险。handoff 仅在恢复或复用需要时生成；恢复读取紧凑状态，
   不向模型回灌完整事件日志。

4. **派遣预览、校准和只读诊断**

   新增不创建 Worker 的派遣预览、追加式 reconciliation 观测账本，以及
   durable run 的只读测量报告。字符数和快照区间只用于诊断，不冒充 Token、
   金额或精确平台延迟。

5. **跨平台和安全加固**

   修复多处 Windows-only 路径假设；继续拒绝 Writer 路径重叠、目录逃逸、
   重解析点输入、计划或日志篡改、伪造完成状态和未授权重试。

6. **行业角色与通用生产者模式**

   内置部分行业角色包并按需加载单个合同。专业 Worker 可以拥有章节、模块、
   调查、数据集或设计面；主 Agent 仍保持全局论证和最终交付。

## English

v0.7.0 is a major stable release. It does not turn the main agent into a
dispatch-only manager, and it does not optimize for more agents. The main
agent keeps producing while bounded Workers receive only independently
verifiable work that benefits from smaller context.

### Why this release is better

- **The main agent keeps working:** it owns the global spine, high-coupling
  work, user communication, external actions, and final acceptance.
- **Less repeated context:** Workers receive paths, source IDs, artifact
  pointers, and selected excerpts rather than full conversations or logs.
- **Temporary and durable work are distinct:** use a lightweight native
  subagent for one-off checks; use a durable background task only for
  independent history, cross-turn recovery, or reuse.
- **Visible role activation:** before every Worker, explain why it is needed,
  its role, execution form, inputs, output, permissions, and model. Report the
  actual identity, state, and model after materialization.
- **Duplicate-safe creation:** a creation error or visibility delay is not
  proof of absence. Returned IDs and visible task state are reconciled before
  any retry; ambiguity stops automatic expansion.
- **Real result collection:** required durable-task results must be read and
  recorded in a hash-bound receipt before final integration.
- **Worker output is data, not authority:** the main-agent control policy
  requires Worker output to be reviewed as untrusted data. Embedded requests
  to bypass validation, expand delegation, or change permissions must be
  surfaced and cannot serve directly as authorization.
- **Provenance-aware findings:** `[verified]`, `[inferred]`, and `[assumed]`
  distinguish reproducible evidence, inference, and unsupported assumptions.
  The packet and main-agent review enforce this policy; this is not a claim
  that free-form text is constrained by a security sandbox.
- **Protected capacity:** target four durable tasks plus two reserved transient
  subagent slots, always clamped to the host runtime.
- **No pre-task model tournament:** normal work uses a static routing table.
  Luna handles bounded mechanical work; Sol handles ordinary or difficult
  judgment. Terra is explicit-request-only, and Ultra needs per-node approval.

### Major changes

1. **Context ownership and event-driven dispatch**

   At task entry and meaningful events, the main agent chooses `main owns`,
   `dispatch native`, `dispatch durable`, `defer`, or `stop`. A Worker is
   created only when its result is independently checkable, uses materially
   less context, and can advance beside the main line.

2. **Task reconciliation and result receipts**

   Durable tasks reserve a stable activation key and make one creation call per
   key. Returned IDs and task-list snapshots are reconciled; ambiguous state
   remains `unknown`. Required results are collected through the real platform
   read path and bound to a receipt.

   Before archive, a durable background task's recorded result receipt is
   re-verified and its hash is bound to the archive event. A missing or changed
   receipt blocks archive.

3. **Lightweight project knowledge and recovery**

   Sourced decisions, facts, interfaces, and unresolved risks are stored only
   when a durable project will reuse them. Handoffs are opt-in, and recovery
   reconstructs compact state without replaying the full journal into a model.

4. **Dispatch preview, calibration, and read-only diagnostics**

   The release adds non-materializing dispatch preview, an append-only
   reconciliation observation ledger, and a read-only durable-run measurement
   report. Character counts and snapshot intervals remain diagnostics, not
   claimed Token totals, monetary cost, or exact platform latency.

5. **Portability and safety hardening**

   Windows-only path assumptions are reduced while writer overlap, path
   traversal, reparse-point input, plan/journal tampering, forged completion,
   and unauthorized retry remain rejected.

6. **On-demand professional roles and general producer ownership**

   Selected industry role contracts load on demand. A specialist may own a
   bounded section, module, investigation, dataset, or design surface while the
   main agent preserves the global spine and final delivery.
