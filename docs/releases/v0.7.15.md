# Adaptive Agent Orchestrator v0.7.15

[简体中文](#简体中文) · [English](#english)

Release date: 2026-07-31

## 简体中文

### 解决的问题

真实长期审核出现了一种很窄、但无法靠现有合同恢复的登记错误：

- 两个审核来源的 `completed` 都正确绑定 result；
- 两个 `adopted` 都正确绑定 disposition；
- 但两个 `validated` 都重复绑定了 result，漏掉 disposition。

旧控制层正确拒绝选择这组证据。问题在于，既不能修改不可变历史，也不应该
重发已经完成的审核，更不能为了修正一个登记指针而重新创建审核员。因此业务
审核已经完成，控制流程却停在最后一步。

### 本版修复

- 新增一个严格的、完整来源集合的 append-only lifecycle evidence
  correction。它只为上述精确错误形态追加纠正证据，不修改旧事件。
- 纠正同时绑定 run、plan、genesis、待处理 revision、预先确定的 selection
  key、写入前日志 head/count、checkpoint、input、两个来源的角色与 thread、
  六条精确生命周期事件，以及 result/disposition 的路径、内部哈希和文件
  哈希。
- 纠正不改变来源状态、不解决问题、不重发审核、不创建审核员，也不能修复
  其他错误形态。
- 后续 selection 与 completion 必须同时验证原始事件和纠正记录。部分来源、
  重复或分叉纠正、跨 run/source/role/thread/revision/checkpoint/input
  复用、授权变化或产物漂移都会在写入前拒绝。

### 实际收益

一次证据指针登记错误不再迫使用户改写历史或重做审核；同时，纠正机制不能被
用来把开放问题“纠正掉”。

真实 checkpoint15 run 中：

- 原 35 条事件前缀逐字节不变；
- 只追加 correction 与 schema 1.2 selection 两条事件；
- 两个审核来源仍为 `adopted`；
- completion 继续因 1 个产品 P0、6 条开放 P1 和缺少主任务验收而
  `BLOCKED`；
- 已解决的 P1-08 没有回流；
- multi-divination 的 90 个产品文件全部保持原哈希。

### 验证

- 54 个 PowerShell 脚本解析；
- 128 项 durable milestone/revision 专项断言；
- 862 项完整自测，59 个非法案例正确拒绝；
- 8 个 reference JSON 文件严格解析；
- Skill Creator 校验；
- 固定 ZIP、功能提交和安装副本 73/73 文件一致；
- 同一独立验收角色完成 39/39 动态攻击，P0/P1/P2 均为 0；
- 真实 correction → selection → completion 采用链通过，并保持预期阻断。

### 边界

- 本版不修复平台 `systemError` 或 final 丢失。
- 本版不判断或修复 multi-divination 的业务 P0/P1，也没有修改其产品文件。
- 本版不声明生产环境 Token 节省或业务准确率。
- correction 不是通用日志编辑器，只接受所有必需来源都满足精确错误形态的
  pending revision。
- 本地追加式哈希链不能抵抗攻击者一致重写早期授权和全部后续历史；该威胁
  仍需要外部不可变锚点。
- Windows 符号链接夹具因权限限制跳过；Linux/macOS 未动态验证。

编排 policy 仍为 `0.7.6`。v0.7.15 是该 policy 下的控制补丁，不要求改写
内部一致的现有 plan、run 或 journal。

## English

### The problem

Real long-lived review exposed a narrow lifecycle-recording error that the
existing contract correctly rejected but could not recover:

- both sources' `completed` events correctly bound their result receipts;
- both `adopted` events correctly bound their disposition receipts; and
- both `validated` events repeated the result pointer instead of binding the
  disposition.

The selection gate failed closed. Editing immutable history was forbidden,
rerunning completed reviews was unnecessary, and creating new reviewers merely
to repair one evidence pointer would have been wrong. The reviews were done,
but the control flow could not select them.

### Fix

- Add one strict, whole-source, append-only lifecycle evidence correction for
  that exact error shape. Original events remain unchanged.
- Bind the run, plan, genesis, pending revision, pre-authorized selection key,
  pre-write journal head/count, checkpoint, input, both source role/task
  identities, all six exact lifecycle events, and result/disposition path,
  internal hash, and file hash.
- Keep every source state unchanged. Correction cannot resolve findings,
  resend review, create a reviewer, or repair another error shape.
- Require selection and completion to verify both the original events and the
  correction. Partial, duplicate, forked, cross-identity, cross-checkpoint,
  authority-drift, and artifact-drift attempts fail before journal write.

### Benefit

A single evidence-pointer mistake no longer forces history editing or repeated
review, while the correction path cannot make an open finding disappear.

In the real checkpoint15 run:

- the original 35-event prefix remained byte-identical;
- only correction and schema 1.2 selection events were appended;
- both reviewer sources remained `adopted`;
- completion stayed `BLOCKED` by one product P0, six open P1 occurrences, and
  missing main acceptance;
- resolved P1-08 did not reappear; and
- all 90 multi-divination product-file hashes remained unchanged.

### Validation

- 54 PowerShell scripts parsed;
- 128 durable milestone/revision focused assertions;
- 862 full self-test assertions and 59 rejected invalid cases;
- 8 strict reference JSON parses;
- Skill Creator validation;
- fixed ZIP, functional commit, and installed Skill matched across 73/73 files;
- the same independent reviewer passed 39/39 dynamic attacks with
  P0=0/P1=0/P2=0; and
- the real correction → selection → completion adoption chain passed while
  preserving the expected block.

### Boundaries

- This release does not repair platform `systemError` or missing-final behavior.
- It does not judge or repair multi-divination P0/P1 findings and did not modify
  multi-divination product files.
- It does not claim measured production Token savings or business accuracy.
- Correction is not a general journal editor. It accepts only a pending
  revision where every required source has the exact qualifying error shape.
- The local append-only hash chain does not resist coherent rewriting of early
  authorization and all later history; that threat still requires an external
  immutable anchor.
- The Windows symbolic-link fixture was skipped; Linux/macOS were not
  dynamically validated.

The orchestration policy remains `0.7.6`. v0.7.15 is a control patch under that
policy and does not require rewriting a consistent existing plan, run, or
journal.
