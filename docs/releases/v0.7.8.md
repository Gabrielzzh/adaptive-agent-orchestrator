# Adaptive Agent Orchestrator v0.7.8

[简体中文](#简体中文) · [English](#english)

Release date: 2026-07-30

## 简体中文

### 解决的问题

长期审核的 successor run 可能在首个里程碑前因主控改变 checkpoint 而取消
某个 source。旧合同会正确把该 source 留在 `cancelled`，却没有合法路径继续：
不能重启 terminal node，不能重置 attempt，也不能复制目录或手改 journal。
结果是复审尚未真正发出，整个控制 run 却永久无法履行。

### 本版收益

- 先生成独立、不可覆盖的 controller authorization，再允许 export；export
  不能自行制造或替换授权。
- 只允许首代 successor 在首个 durable milestone、主验收、复审消息和结果
  生命周期之前进入 abandonment 路径。
- 单次 export 绑定旧 successor adoption、最终 journal head/count、取消事件、
  `no-review-message-dispatched` 证据、checkpoint、原 source/role/thread、
  全部继承与新增 P1，以及 fresh plan/run/milestones。
- fresh successor adoption 保留每个 source 已消耗的 attempt；不能把取消过的
  source 重置成第一次启动，也不能更换角色、thread 或来源。
- 旧 plan/run/genesis/journal 不被改写；旧未激活 result/disposition 只作为
  `completion_eligible=false` 的证据，不能满足完成门。
- 重复或分叉 export、跨 run/source/thread/checkpoint 重放、漏项、降级、
  已激活里程碑和已有结果生命周期全部 fail closed。

### 真实采用验证

multi-divination 控制 run 完成了正式的 authorization → export → fresh
adoption：

- 两个原 durable source、role 和 thread 保持不变；
- traditional 携带 attempt 1，下一次只能从 attempt 2 启动；
- 18/18 条 P1 完整继承（traditional 12、adversarial 6），P0=0；
- 新 finding `LY-ADV-R06-P1-001` 没有被合并或遗漏；
- completion 按预期保持 `BLOCKED`，逐条要求 18 项 current same-source
  disposition，旧 P0 和旧 checkpoint 收据没有回流。

### 验证

- 45 个 PowerShell 脚本解析；
- 52 项 abandoned-successor 专项断言；
- 739 项完整自测，59 个非法案例正确拒绝；
- 8 个 reference JSON 文件严格解析；
- Skill Creator 校验；
- 同一独立 Noether 角色动态复攻，P0/P1/P2 均为 0；
- 源码与安装副本 64/64 文件 SHA-256 一致；
- 真实控制面采用 PASS。

### 边界

- 本版不修复平台 `systemError` 或缺失 final。
- 本版不声明生产环境 Token 节省或业务准确率。
- 本版不迁移或修改 multi-divination 产品文件。
- 本地 hash chain 能检测链内变化，但无法抵抗能够重写 authorization、
  journal 与全部后续锚点的完整历史重签；这种威胁需要外部 WORM、签名或
  远程日志锚点。
- Windows 符号链接夹具因权限限制跳过；Linux/macOS 未动态验证。

编排 policy 仍为 `0.7.6`。v0.7.8 增加的是该 policy 下的严格恢复命令，
现有一致的 `0.7.6` run 不需要仅因安装本版而修改历史。

## English

### The problem

A durable-review successor can cancel a source before its first milestone when
the controller changes the checkpoint. The old contract correctly leaves that
source terminally `cancelled`, but offered no legal continuation: the node
could not restart, its attempt could not reset, and copying the run or editing
the journal would destroy its audit identity. Review had never been dispatched,
yet the control run could no longer fulfill its profile.

### Benefits

- A separate append-once controller authorization precedes export; export
  cannot manufacture or replace its own authority.
- Only a first-generation successor before its first durable milestone, main
  acceptance, review message, or result lifecycle can use this path.
- The single export binds the old successor adoption, final journal head/count,
  cancellation and no-dispatch evidence, checkpoint, original source/role/
  thread identities, every inherited and new P1, and the fresh plan/run/
  milestone target.
- Fresh adoption preserves consumed attempts. A cancelled source cannot regain
  attempt 1 or switch role, thread, or logical source.
- The old plan, run, genesis, and journal remain immutable. Unactivated result
  or disposition receipts are explicitly non-completion evidence.
- Forked or repeated export, replay across runs/sources/threads/checkpoints,
  omitted or downgraded obligations, activated milestones, and existing result
  lifecycles fail closed.

### Real adoption

The multi-divination control run completed the formal authorization → export →
fresh-adoption chain:

- both durable source, role, and thread identities stayed unchanged;
- the traditional source carried attempt 1 and can next launch only as attempt
  2;
- all 18 P1 source occurrences were preserved (12 traditional, 6 adversarial),
  with zero P0;
- `LY-ADV-R06-P1-001` remained a distinct additional finding;
- completion correctly stayed `BLOCKED` until all 18 current same-source
  dispositions exist; old P0 and old-checkpoint receipts did not return.

### Validation

- 45 PowerShell scripts parsed;
- 52 focused abandoned-successor assertions;
- 739 full self-test assertions and 59 rejected invalid cases;
- 8 strict reference JSON parses;
- Skill Creator validation;
- dynamic re-attack by the same independent Noether role, with P0/P1/P2 all
  zero;
- 64/64 source and installed Skill files matched by SHA-256;
- the real control-plane adoption passed.

### Boundaries

- This release does not repair platform `systemError` or a missing final.
- It does not claim measured production Token savings or business accuracy.
- It does not migrate or modify multi-divination product files.
- The local hash chain detects in-chain changes, but cannot resist a coherent
  rewrite of authorization, journal, and every later retained anchor. That
  threat requires an external WORM, signature, or remote-log anchor.
- The Windows symbolic-link fixture was skipped; Linux/macOS were not
  dynamically validated.

The orchestration policy remains `0.7.6`. v0.7.8 adds strict recovery commands
under that policy; installing it does not require rewriting a consistent
existing `0.7.6` run.
